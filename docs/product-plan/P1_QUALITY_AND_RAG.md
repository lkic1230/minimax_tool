# P1 任务卡：质量与 RAG 能力

## 阶段目标

- 提升回答可信度与稳定性，让用户看到“有来源、可追溯”的结果。
- 支持用户对本地文档进行问答，减少纯模型幻觉。

## 需求清单（功能视角）

- [ ] `P1-RQ-001` 来源展示：每条联网答案展示来源标题、URL、抓取时间。
- [ ] `P1-RQ-002` 引用映射：答案段落可映射到具体来源片段。
- [ ] `P1-RQ-003` 来源折叠：支持展开/折叠来源明细，减少界面噪音。
- [ ] `P1-RQ-004` 文档上传：支持上传常见文本类文件并显示上传状态。
- [ ] `P1-RQ-005` 文档管理：支持查看已上传文档列表与删除文档。
- [ ] `P1-RQ-006` 文档检索：问答时能从文档中检索相关片段。
- [ ] `P1-RQ-007` 片段引用：回答中展示来自文档的引用片段与定位信息。
- [ ] `P1-RQ-008` 多文档场景：同一问题可跨多个文档检索并汇总。
- [ ] `P1-RQ-009` 长会话压缩：达到阈值后自动摘要历史上下文。
- [ ] `P1-RQ-010` 摘要可见：用户可看到“已压缩上下文摘要”的提示。
- [ ] `P1-RQ-011` 重试策略A：请求超时自动重试并记录次数。
- [ ] `P1-RQ-012` 重试策略B：限流场景按退避策略重试。
- [ ] `P1-RQ-013` 重试策略C：网络抖动场景短间隔重试。
- [ ] `P1-RQ-014` 错误提示：失败时区分“可重试”和“需用户处理”。
- [ ] `P1-RQ-015` 质量回退：联网不可用时回退为本地知识回答并提示风险。

## 用户体验要求

- 用户能够判断回答“来自哪里”。
- 文档问答能定位到原文片段，而不是只给笼统结论。
- 长会话场景下，不明显退化、不频繁丢上下文。

## 建议开发顺序（Wave）

- `Wave 1（先做可信回答）`：`P1-RQ-001~003`
- `Wave 2（做文档问答）`：`P1-RQ-004~008`
- `Wave 3（做稳定性）`：`P1-RQ-009~014`
- `Wave 4（做降级兜底）`：`P1-RQ-015`

## 测试点（验收）

- [ ] `P1-TC-001` 3 组联网问题中，回答均有来源标题、URL、抓取时间。
- [ ] `P1-TC-002` 来源展开后可看到对应引用片段，且与答案语义一致。
- [ ] `P1-TC-003` 上传 2 种不同格式文档后，均可完成问答与片段引用。
- [ ] `P1-TC-004` 多文档问答中，答案可同时引用 2 个以上文档来源。
- [ ] `P1-TC-005` 50+ 轮会话后，系统出现上下文压缩提示且语义连续。
- [ ] `P1-TC-006` 模拟超时/限流/网络抖动时，重试次数与提示符合预期。
- [ ] `P1-TC-007` 联网失败时有明确降级提示，不出现静默失败。
