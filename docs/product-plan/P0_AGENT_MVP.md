# P0 任务卡：Agent MVP（最高优先级）

## 阶段目标

- 让用户输入一个目标后，系统能分步执行并输出可交付结果。
- 完成“可见过程 + 可验收结果”的最小 Agent 闭环。

## 需求清单（功能视角）

- [ ] `P0-RQ-001` 任务创建：支持输入任务目标与补充约束（例如输出格式、截止时间）。
- [ ] `P0-RQ-002` 任务状态：支持 `待执行/执行中/已完成/失败/已取消` 的可视化状态。
- [ ] `P0-RQ-003` 步骤列表：展示每一步的名称、开始时间、结束时间、耗时。
- [ ] `P0-RQ-004` 当前步骤高亮：执行中步骤在界面中有明确高亮标识。
- [ ] `P0-RQ-005` 结果总览区：提供结论摘要、关键依据、未完成项。
- [ ] `P0-RQ-006` 工具调用记录：每一步可查看输入摘要、输出摘要、错误摘要。
- [ ] `P0-RQ-007` 工具能力A：支持联网搜索并返回来源链接。
- [ ] `P0-RQ-008` 工具能力B：支持网页正文抓取并返回结构化文本。
- [ ] `P0-RQ-009` 工具能力C：支持本地文件读取与写入（受控目录）。
- [ ] `P0-RQ-010` 手动确认机制：高风险步骤执行前要求用户确认或拒绝。
- [ ] `P0-RQ-011` 用户中断能力：执行中支持手动停止任务。
- [ ] `P0-RQ-012` 错误恢复入口：失败步骤支持“重试当前步骤”。
- [ ] `P0-RQ-013` 结果复制：支持一键复制任务结果文本。
- [ ] `P0-RQ-014` 结果导出：支持导出为文本文件。
- [ ] `P0-RQ-015` 历史可追溯：任务完成后可回看步骤日志与最终结果。

## 用户体验要求

- 用户发起任务后，不需要反复追问“现在做到哪一步”。
- 步骤失败时给出明确原因与下一步建议，不静默失败。
- 结果必须包含结构化摘要（结论、来源、待确认项）。

## 建议开发顺序（Wave）

- `Wave 1（先做底座）`：`P0-RQ-001~006`
- `Wave 2（接工具能力）`：`P0-RQ-007~009`
- `Wave 3（补交互闭环）`：`P0-RQ-010~012`
- `Wave 4（补交付与追溯）`：`P0-RQ-013~015`

## 测试点（验收）

- [ ] `P0-TC-001` 输入“调研某主题并给结论”时，能看到 `创建 -> 执行 -> 完成` 全链路。
- [ ] `P0-TC-002` 每个步骤都记录开始/结束时间，耗时计算正确。
- [ ] `P0-TC-003` 联网搜索结果至少包含来源链接，且可点击。
- [ ] `P0-TC-004` 网页抓取失败时，失败原因对用户可见。
- [ ] `P0-TC-005` 本地文件读写仅在允许范围内生效，越权路径被拒绝。
- [ ] `P0-TC-006` 人工确认弹窗中选择“拒绝”后，高风险步骤不会执行。
- [ ] `P0-TC-007` 执行中点击“停止任务”后，状态变更为“已取消”。
- [ ] `P0-TC-008` 单步失败后点击“重试当前步骤”，可重新进入执行状态。
- [ ] `P0-TC-009` 导出文件内容与结果总览区一致。
- [ ] `P0-TC-010` 连续执行 5 个任务后，任务日志不会串线或覆盖。
